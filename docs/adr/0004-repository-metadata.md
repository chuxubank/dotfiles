# Separate repository metadata from paths

`path.toml` consumers require string leaves and care only where resources live. Embedding clone URLs, branches, refresh periods, and host conditions there would make every path lookup understand repository metadata. Keeping those facts in per-group external templates had the opposite problem: paths and clone behavior were split across files, every group reimplemented rendering and gating, and a new path key did not reveal whether it needed a clone.

`repositories.yaml` now maps a `path.toml` key path to git clone metadata. Its interface is `path`, optional `dest`, `url`, `refresh_period`, optional `branch`, optional `depth`, and optional shared `when` conditions. `repositories.toml.tmpl` resolves and validates paths, evaluates host conditions, and renders every git-repo external; specialized non-git externals remain separate. This keeps path consumers simple while making repository ownership, placement, gating, and destination uniqueness reviewable in one data file.

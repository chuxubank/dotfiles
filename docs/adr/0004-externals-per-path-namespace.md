# Lay out externals files by path namespace

`.chezmoiexternals/` filenames had drifted from `path.toml`. `sideline.toml.tmpl` mixed OpenXingZhi repos with the upstream `qmk_firmware` checkout, `asahiart.toml.tmpl` sat beside it as a second side-project org file, and a `keyboard.toml.tmpl` grouped `path.personal.keyboard` with `path.workspace.qmk` across two namespaces. Nothing told you which file a new `path` key belonged in. The alternative was to make the grouping structural with a `[path.sideline]` subnamespace, but `trust/paths`, `dot_codex/modify_private_config.toml`, `environment.yaml`, and `.chezmoiignore` all consume `path.workspace` and care only about the path, so each would have to merge two lists to learn nothing.

One file now holds one `path` namespace, or one semantic group inside a namespace: `path.personal` in `personal.toml.tmpl`; the Infinity Valley work tree `path.workspace.iv` in `iv.toml.tmpl`; the side-project org trees `path.workspace.asahiart`, `path.workspace.opentactic`, and `path.workspace.xz` in `sideline.toml.tmpl`; `path.workspace.qmk` alone because it is an upstream checkout and the only role-gated entry; `path.tool` plus `path.cache` in `common.toml.tmpl`. Work tree `aa` is cloned by hand and has no external. `darwin.toml.tmpl` and `zotero.toml.tmpl` stay outside the scheme because a platform gate and an application's plugin set are not path namespaces. `path.toml` carries a comment on `[path.workspace]` recording the split, so the file layout is derivable from the data rather than from these filenames.
